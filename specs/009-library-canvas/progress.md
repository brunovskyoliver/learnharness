- 2026-10-30 Technical choices the contracts leave open (reversible, logged per constitution I): a document's `updatedAt` is its bytes' mtime and a rename keeps it, which is what lets reconcile recover a mid-rename crash without a new field. A rename to a different kind is allowed only if the bytes pass that kind's content check, otherwise 400. Files whose names break the name rules (never producible by uploads) stay on disk but are not listed. Stale `<data>/tmp/upload-*` older than a day are swept on listing.

- 2026-10-30 Phase 3 choices (reversible, logged per constitution I): "New page" is not rendered until Phase 5 (T059), because a button with no page store would be a phantom state; the approved empty sentence stays verbatim and mentions a page meanwhile. - 2026-10-30 Phase 4 choices (reversible, logged per constitution I): the message limit counts outlines too, but an outline is never refused, so a message can pass 64 KiB by up to its outlines. An unreadable catalog gives no references and a log line, and the input is saved. A read error or a PDF pdfjs can't open is `unreadable`, `no-text`, since the contract has no other label for it. `LibraryReference` gains optional `pages` for the no-text sentence. Empty "I don't know" has no text to parse; one with typed reasoning still parses it (research R9). The @ list sits in the shell's flow above the field, because the chat shell clips what leaves it. The label's name opens the content route in a new tab until T059 moves text kinds to the pane; pages have no link yet. Library tools reach the agent as an injected context (lint forbids the store there); `image` jobs carry id, name and question, and the runner finds the file. Sentences the contracts don't word (agent-facing reference sentences, "Image reader", the image result row) are for owner review.

- 2026-10-30 Phase 5 choices (reversible, logged per constitution I): TipTap 3.32.2 pinned exactly, plus `decode-named-character-reference` 1.3.0 (already installed under `mdast-util-from-markdown`) so `&copy;` round-trips. The app's Markdown extension is not used: `components/library/page-markdown.ts` holds its own `MarkdownManager` and patches three of its internals (escaper, HTML tokens, marks on atoms), guarded by the pinned version and the corpus test. Math stores its exact delimiters as attributes. Raw HTML and footnote definitions show as editable source, inline HTML and footnote calls as source chips. An untouched block writes back its original bytes; once any block is edited, the blocks' separators become one blank line and link definitions become inline links. Saving text equal to the newest version makes no version. Drafts and versions share one tenant lock rather than one per page. `rev` takes the clock when ahead, so a cleared draft's rev is never reused. Use latest is two steps: commit the tab's text with `conflict`, then restore the newest, attributed to You. A backup is per tab, one localStorage key each; a tab with none picks up the newest other one. A reload's text returns silently as "Not saved" until sent, instead of a separate offer, because the contract has no words for one. "New page" names itself "Untitled page". A page's lone image is wrapped back in its paragraph. A key pressed with a formula selected is ignored; Backspace still removes it. Strings the contract doesn't word, for owner review: "Edit math", "TeX source", "Save", "Cancel" in the math dialog; "The history could not be loaded."; "A page can be at most 1 MB."; "This page is no longer..." route errors; "The page could not be created.". For the owner: bold demo titles link only in the History preview (T061 as written), not in the live editor, where a click places the caret. The Library has "New page"; spec US3.1 also says "or a session", and the contract gives no control for it, so sessions have none yet.

For the owner: T070's native-focus list in components/chat.tsx was not extended; the task leaves that to him.
